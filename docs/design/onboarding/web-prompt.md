请为 Vela Wallet Web 端重构项目做好准备，并实现首个页面（Onboarding）。

项目目标：在 `app-web/vela-wallet` 中使用 SvelteKit 重写现有 VelaWallet，确保架构清晰、可维护，并为后续页面扩展建立统一基础。

工作要求：

1. 分支与项目准备
   - 从当前开发基线创建一个新分支，分支名使用 `codex/` 前缀。
   - 先了解现有 VelaWallet 的功能、目录结构和可复用资源；除本任务必要改动外，不修改无关代码。

2. 设计系统接入
   - 以项目中的 `docs/design-system.md` 为唯一设计规范来源，完成颜色、排版、间距、圆角、阴影、组件状态等基础设计令牌的接入。
   - 建立可复用的基础 UI 组件和样式机制，避免在页面中散落重复的颜色、尺寸或样式定义。
   - 支持浅色与深色模式，并确保两种模式下的可读性与视觉一致性。

3. 国际化与本地化
   - 研究并接入 `rust/crates/vela-core` 中现有的 i18n/l10n 资源、格式和约定，避免重新定义一套不兼容的翻译体系。
   - 明确验证该国际化方案能否在 SvelteKit 中支持 SSR 渲染。
   - 输出简短结论，说明：
     - 是否可实现服务端渲染的多语言内容；
     - 对 SEO 的影响；
     - 推荐的实现方案、限制和必要的技术调整。
   - 不要仅在客户端加载翻译后再渲染关键页面内容；首屏可索引文本应尽可能在服务端完成渲染。

4. 首发页面：Onboarding
   - 实现 Onboarding 页面，设计参考目录：
     `/Volumes/data/production/vela-wallet/design/onboarding`
   - 尽量忠实还原设计稿，同时遵循 `docs/design-system.md`。
   - 如设计稿存在缺失、冲突或无法确定的交互，采用与现有产品风格一致的合理默认方案，并在交付说明中列出。

5. 响应式与布局要求
   - 同时支持桌面端和移动端。
   - 当视口宽度小于 `1280px` 时，使用移动端布局；大于等于 `1280px` 时，使用桌面端布局。
   - 不是简单缩放桌面页面，而是应按移动端信息层级和交互习惯组织布局。
   - 页面在常见桌面和手机尺寸下不应出现横向溢出、内容遮挡或不可操作的控件。

6. 工程质量
   - 保持高内聚、低耦合：页面负责页面编排，通用逻辑和通用 UI 应提取到合理的模块中。
   - 同一业务规则、设计令牌或交互逻辑只维护一处，避免重复实现和分散配置。
   - 组件 API 应简洁，目录结构清晰，便于后续新增页面和维护。
   - 为关键组件、主题切换、国际化加载和响应式布局提供必要的验证。
