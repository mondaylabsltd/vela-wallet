# 轉帳與收款

## 收款

1. 打開錢包，點**收款**。
2. 把位址給出去——複製它，或是讓對方掃 QR Code。
3. 轉帳在鏈上確認之後，餘額就會出現在你的錢包裡。

有兩件事值得知道：

- 你的位址**在每一條支援的網路上都一樣**，所以到處給同一個位址就好——只要確認
  對方用的是正確的網路。
- 你**可以在錢包合約部署之前就收款**。Vela 的帳戶是反事實智慧帳戶，所以在某條鏈
  上合約還不存在的時候，錢就已經能進到你的位址；等你第一次在那條鏈上送出交易時，
  它會把自己部署上去。

## 轉帳

1. 點**轉帳**，選**代幣**。
2. 輸入**金額**（可以在代幣和你的顯示貨幣之間切換）和**收款方**。只要認得出來，
   Vela 會把已知的收款方顯示成名字——一個 Vela 帳戶、一個 ENS 名稱、一個 Basename
   等等。
3. **核對並確認。** Vela 把這筆轉帳擺給你看，然後請你用密碼金鑰
   （Face ID / Touch ID / 指紋）確認。

### 你按下確認之後發生了什麼

Vela 不只是把交易「廣播」出去。底層是這樣的：

1. 它為你的 Safe 帳戶組出一個 ERC-4337 **UserOperation**。
2. 你的裝置在生物辨識之後，用一次 **WebAuthn（P-256）**斷言替它簽署。
3. 簽好的操作送到**中繼**，由它提交給 EntryPoint；你的 Safe 在**鏈上**驗證
   這個 P-256 簽章，然後執行。

<Callout type="info" title="中繼動不了你的交易">
中繼收到的是一份<strong>已經簽好</strong>的 UserOperation。它可以拖延，也可以
拒絕轉送，但改不了收款方、金額或是任何其他欄位——任何改動都會讓你的簽章失效。
它是幫你上鏈的角色，不是保管方，而且它開放原始碼，你可以自己跑一個。
</Callout>

### 清晰簽署——不做盲簽

在你簽署之前，Vela 會用 **ERC-7730** 描述符解碼這筆交易，顯示它的**意圖**
（轉帳、授權、兌換……）、**金額和位址**，以及一個風險提示——而不是一串看不懂的
十六進位。當它沒辦法完整解碼一個呼叫時，它會給出明確的**盲簽警告**，而不是假裝
自己看懂了。無限額度的代幣授權不只是被標記——Vela 會把它改寫成一個有限的金額，
並且拒絕提交任何仍然無限的授權。

## 按下送出之前

- **核對位址的前幾碼和後幾碼。** 會替換位址的惡意程式是真的存在。
- **確認網路。** 送錯網路是最常見、也最貴的失誤。見[網路與費用](/zh-TW/docs/networks-and-fees)。
- **對新的收款方先小額試一次。** 先轉一筆很小的錢，是很便宜的保險。

交易不可逆。轉錯位址之後，沒有任何客服能幫你把錢要回來——這就是自我保管的本質。

## 怎麼看歷史紀錄

餘額和歷史紀錄是從一組公開 RPC 節點即時讀取的，而且會自動容錯切換。如果網路慢，
歷史可能要等一下——轉圈的意思是「還在抓」，不是「錢不見了」。
