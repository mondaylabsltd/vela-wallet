# 網路與費用

## 支援的網路

Vela 內建 **12 條 EVM 網路**：

| 網路 | 原生手續費代幣 |
| ----------- | ---------------- |
| 以太坊 | ETH |
| BNB Chain | BNB |
| Polygon | POL |
| Arbitrum | ETH |
| Optimism | ETH |
| Base | ETH |
| Avalanche | AVAX |
| Gnosis | xDAI |
| Unichain | ETH |
| Tempo | USD |
| Monad | MON |
| World Chain | ETH |

你的錢包**在所有這些網路上都是同一個位址**，所以到處給同一個位址就好。

你也可以**新增自訂網路**（設定 → 網路）。因為 Vela 是智慧帳戶錢包，所以一條網路
必須提供 Vela 依賴的那些合約——ERC-4337 EntryPoint、Safe 合約，以及在鏈上驗證你
密碼金鑰的 **P-256（RIP-7212）**簽章預編譯。在讓你新增一條網路之前，Vela 會自動
檢查這些。

<Callout type="info" title="為什麼 Gnosis 出現得特別多">
除了是這 12 條網路之一，Gnosis Chain 還承載著 Vela 的**密碼金鑰索引**——那份為了
跨裝置復原而保存你公鑰和帳戶名字的合約。它和你在哪條網路上交易是兩回事。
</Callout>

## 費用怎麼算（帳戶抽象）

Vela 使用 **ERC-4337 帳戶抽象**，所以一筆交易不是由你直接廣播的——它是一個
**UserOperation**，交給一個**中繼**，由它提交上鏈並拿回 gas 的補償。（ERC-4337
規範把這個角色叫作 *bundler*。Vela 這一份叫中繼，是因為它做的不只是打包：它
帶內報價，還執行下面那套 gas 帳戶協定，這兩件事都不在標準裡。）由此帶出幾件事：

- **gas 從你自己錢包的餘額付**——預設用該網路的原生代幣（ETH、BNB、xDAI……），
  或是在中繼提供支援的地方用某種穩定幣；費用資產在確認頁上由你選。Tempo 沒有原生
  幣，所以那裡的 gas 一律用美元穩定幣結算。這裡沒有 ERC-4337 的 **paymaster** 來
  贊助——或是卡住——每一筆交易。（Vela 可能會替新使用者贊助那次一次性的
  *gas 帳戶啟用*；那是另一回事，下面會談。）
- **gas 價格由中繼報出**——它是唯一的事實來源，錢包顯示這份報價，而且簽的就是它
  顯示的東西。這裡沒有速度選擇器：每一筆交易都以高優先度提交。
- 總費用是**網路成本加上中繼的服務費**，非常便宜的交易會有一個很小的最低收費。
  中繼的報價就是價格——不存在另一份要去查的費率表。其中一部分歸這條鏈的驗證者；
  剩下的付給那個墊付 gas、並且維運這套基礎設施的中繼方。
- 確認頁在你簽署前，會用費用資產和你的顯示貨幣兩種形式呈現**預估費用**。報出的
  金額和它的收款方都是你所簽內容的一部分，所以中繼拿到的分毫不差就是顯示過的那個數
  ——數字一改，你的簽章就失效了。

## 誰在運行中繼——費用又歸誰

每一條網路都指向一個中繼。預設是 **Vela 自己的中繼**，你可以在
*設定 → 進階 → 服務端點* 裡替換這個位址。一個端點對所有內建網路生效；自訂網路
則沿用你新增它時填的那個中繼位址。

關於相容性有一句老實話：應用是透過一個 Vela 專屬的 RPC 方法
（`vela_getInBandGasQuote`）取得費用報價的，沒有它，轉帳流程就走不下去。所以
你指過去的那個端點必須跑著
[vela-relay](https://github.com/mondaylabsltd/vela-relay)——Vela 的執行個體，或是你
自己架的一份。像 **Pimlico** 或 **Alchemy** 這類通用 ERC-4337 bundler 沒有實作
這個方法，所以在目前版本裡沒辦法端到端跑通。

誰在替一條網路運行中繼，**誰就收走那條網路上的費用**——每筆交易的中繼加價，
以及 gas 帳戶的啟用押金。自己跑一份 vela-relay，這些費用就去養你自己的基礎設施，
而不是 Vela 的；你導到別處的流量，Vela 不抽一分。

<Callout type="warning" title="gas 帳戶是 vela-relay 協定的一部分">
**gas 帳戶啟用**這一步，是在每條網路上替你的錢包出資建立一個專屬的中繼帳戶。
如果你把端點指向自己架的 vela-relay，這筆押金進的是你自己中繼的帳戶，不是 Vela 的。
</Callout>

### 啟用 gas 帳戶（Vela Relay）

在 Vela 的中繼上，你在每條網路上的第一筆交易會**啟用一個專屬的 gas 帳戶**。應用會
先請求中繼的資金池替你出這筆錢——這一步在轉帳流程裡默默完成，被贊助到的錢包
根本不會看到任何出資畫面。只有當贊助被拒絕時，應用才會顯示一個儲值請求：你往它
顯示的那個 gas 帳戶位址轉一小筆原生代幣，同時它會告訴你為什麼這次沒有贊助。

**拿不到免費贊助時，啟用費由你自己付**——也就是下面這些情況：

- **Vela 在那條網路上的資金池空了或是快空了** —— 那條鏈上的免費額度暫時用盡。
- **你把免費額度用完了** —— 贊助是以錢包為單位設上限的，超過前幾次之後就自費。
- **Vela 的中繼根本不替那條網路出資** —— 例如**你自己新增的自訂網路或測試網**，
  Vela 在上面沒有任何資金池。（如果你寧願完全跳過啟用，就把它們導到自己的中繼。）

這筆啟用押金**不可退還**——它是中繼帳戶的起始餘額，之後會從 gas 退款裡慢慢補回來，
不過它仍然可能被耗盡，之後需要**重新啟用**。服務升級時中繼位址也可能變更，那也需要
重新啟用一次。

費用從你選定的**費用資產**餘額扣——預設是原生代幣。如果一次轉帳因為 gas 被擋下，
表示你那個費用資產的餘額不夠付費用；在中繼提供穩定幣 gas 的地方，在確認頁上換一種
費用資產就能解開。

當你轉出某種原生代幣的**最大金額**時，Vela 會自動預留足夠的 gas，好讓交易不會失敗。

## Vela 怎麼跟每條網路打交道

Vela 讀取餘額和提交交易走的是**一組 RPC 節點**，而不是單一供應商。它從多個來源
蒐集節點，按延遲和可靠度評分，並在某個節點慢了或是掛了時**自動切換**——把壞節點
暫時冷凍——這樣單一個不穩定的節點永遠不會讓整個應用下線。
