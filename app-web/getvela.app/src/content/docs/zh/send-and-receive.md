# 转账与收款

## 收款

1. 打开钱包，点**收款**。
2. 把地址给出去——复制它，或者让对方扫二维码。
3. 转账在链上确认之后，余额就会出现在你的钱包里。

有两件事值得知道：

- 你的地址**在每一条受支持的网络上都一样**，所以到处给同一个地址就行——只要确认
  对方用的是正确的网络。
- 你**可以在钱包合约部署之前就收款**。Vela 的账户是反事实智能账户，所以在某条链
  上合约还不存在的时候，钱就已经能到你的地址；等你第一次在那条链上发交易时，
  它会把自己部署上去。

## 转账

1. 点**发送**，选**代币**。
2. 输入**金额**（可以在代币和你的显示货币之间切换）和**收款方**。只要认得出来，
   Vela 会把已知的收款方显示成名字——一个 Vela 账户、一个 ENS 名字、一个 Basename
   等等。
3. **核对并确认。** Vela 把这笔转账摆给你看，然后请你用通行密钥
   （Face ID / Touch ID / 指纹）确认。

### 你按下确认之后发生了什么

Vela 不只是把交易「广播」出去。底层是这样的：

1. 它为你的 Safe 账户构造一个 ERC-4337 **UserOperation**。
2. 你的设备在生物识别之后，用一次 **WebAuthn（P-256）**断言给它签名。
3. 签好的操作被送到**中继器**，由它提交给 EntryPoint；你的 Safe 在**链上**验证
   这个 P-256 签名，然后执行。

<Callout type="info" title="中继器动不了你的交易">
中继器收到的是一份<strong>已经签好名</strong>的 UserOperation。它可以拖延，也可以
拒绝转发，但改不了收款方、金额或者任何其它字段——任何改动都会让你的签名失效。
它是一个帮你上链的角色，不是托管方，而且它开源，你可以自己跑一个。
</Callout>

### 清晰签名——不做盲签

在你签名之前，Vela 会用 **ERC-7730** 描述符解码这笔交易，显示它的**意图**
（转账、授权、兑换……）、**金额和地址**，以及一个风险提示——而不是一串看不懂的
十六进制。当它没法完整解码一个调用时，它会给出明确的**盲签警告**，而不是假装
自己看懂了。无限额度的代币授权不只是被标红——Vela 会把它改写成一个有限的金额，
并且拒绝提交任何仍然无限的授权。

## 按下发送之前

- **核对地址的头几位和末几位。** 替换地址的恶意软件是真实存在的。
- **确认网络。** 发错网络是最常见、也最贵的失误。见[网络与费用](/zh/docs/networks-and-fees)。
- **对新的收款方先小额试一次。** 先转一笔很小的钱，是很便宜的保险。

交易不可逆。转错地址之后，没有任何客服能帮你把钱要回来——这就是自托管的本质。

## 怎么看历史记录

余额和历史记录是从一组公共 RPC 节点实时读取的，并且会自动故障切换。如果网络慢，
历史可能要等一下——转圈的意思是「还在取」，不是「钱没了」。
