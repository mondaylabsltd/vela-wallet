# 收款与转账

## 收款

1. 打开钱包，点击**收款**。
2. 分享你的地址——复制，或出示二维码。网页钱包还可以生成带金额的收款请求。
3. 转账在链上确认后，就会出现在你的余额里。

- 你的地址**在每条网络上都相同**，所以只需给出一个地址——但对方仍然必须使用 Vela 支持的网络，或你
  已添加的网络。
- 在某条网络上，**钱包部署之前就能收款**。你第一次从那条网络转出时，它会自行部署。

## 转账

1. 点击**转账**，选择**代币**。
2. 输入**金额**（按代币或按你的显示货币）和**收款地址**：粘贴、扫二维码，或从联系人里选。
3. **核对。**Vela 会显示这笔交易会做什么、手续费，以及它为收款方找到的名字（如果有）。
4. 用你的一把钥匙**确认**——面容、指纹、PIN，或在安全密钥上触碰并输入 PIN。

### 一次转给多人，或归集

- **拆分转账**——在一笔交易里把一种代币转给多个人。可以粘贴名单或导入表格，也可以按你的货币填写金额。
- **归集**——在一笔交易里把多种代币转到同一个地址。

无论哪种，你都只签一次名，这笔交易也只付一次手续费。

### 地址的名字

输入地址后，Vela 会为它查找一个名字：先查自己的注册表（另一个 Vela 钱包的名字），再查 `.bnb`、
`.arb`、`.g`、Basename 和 ENS 的反向记录，都直接从各条链上读取。这是单向的——它给你输入的地址起名。
输入 `alice.eth` 这样的名字并不会去查对应的地址。你保存的**联系人**也会显示名字。

只有当反向记录里的名字**正向解析回同一个地址**时，才会显示出来。
任何人都可以把自己的反向记录设成任意字符串，所以这条记录本身什么也证明不了；
钱包会去问名字服务这个名字指向哪个地址，两边一致才显示这个名字。
如果这项核对做不成——端点不应答、解析器出错——你看到的就是地址、没有名字，
绝不会是一个没核对过的名字。

### 手续费币种和速度

确认页会以手续费币种和你的货币显示手续费。你可以用网络原生币支付，在中继接受的网络上也可以用美元
稳定币，还可以选择速度（默认：快）。转出原生币的**最大金额**时，Vela 会自动留出手续费。
[手续费怎么算](/zh/docs/networks-and-fees)。

### 你确认之后发生了什么

1. Vela 为你的 Safe 构造一个 ERC-4337 **UserOperation**，其中包含付给中继的手续费。
2. 你的钥匙验证你之后，用 **WebAuthn（P-256）**断言为它签名。
3. 签好名的操作交给**中继**，由它提交给 EntryPoint；你的 Safe 在链上检查 P-256 签名后执行。

<Callout type="info" title="中继改不了你的交易">
中继收到的是已经签好名的操作。它改不了收款方、金额或手续费——任何改动都会让你的签名失效。它可以
延迟或拒绝，也决定交易何时上链。它是开源的，你也可以[自己运行一个](/zh/docs/self-hosting#relay)。
</Callout>

签名之前，Vela 会解码这笔交易做什么，并对它解不开的部分给出警告；见[清晰签名](/zh/docs/clear-signing)。

## 点下转账之前

- **核对地址的开头和结尾。**替换地址的恶意软件确实存在，被人故意塞进你交易记录里的相似地址也是。
- **确认网络。**选错网络是常见又昂贵的错误。
- **给新收款方先小额试一下。**一笔很小的测试转账，是很便宜的保险。

交易无法撤回。转错了地址，谁也追不回来——自托管就是这样。

## 你的交易记录

你的交易记录由两部分组成：你在这台设备上发出的交易，以及从各条链的日志里读到的代币转账。在某些网络
上，经由其他合约转给你的原生币（比如部分交易所提现）不一定会产生日志，所以可能余额里有、记录里却看
不到。余额通过一组可自动切换的 RPC 节点实时读取；转圈表示“还在读取”，不是“钱没了”。
