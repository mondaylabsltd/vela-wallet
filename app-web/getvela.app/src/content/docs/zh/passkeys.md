# 通行密钥如何工作

控制 Vela 钱包的钥匙是**通行密钥**：P-256 曲线上的 WebAuthn 凭证。每一把都由你的设备或
安全密钥生成并保管私钥，只有在你用面容、指纹、设备密码，或在安全密钥上触碰并输入 PIN
确认之后才会使用。包括 Vela 在内，任何 App 都读不到私钥。

## 通行密钥是什么

通行密钥是为某一个网站生成的一对公私钥——对 Vela 来说是 `getvela.app`。App 永远拿不到
私钥，只能请认证器签名，而认证器会先征得你的同意。

私钥放在哪里，取决于钥匙的种类：

| 钥匙种类 | 私钥在哪里 | 会同步到其他设备吗 |
| --- | --- | --- |
| **本设备**——面容 ID、触控 ID、指纹、Windows Hello | 系统的密码管理器（iCloud 钥匙串、Google 密码管理器）或 1Password 等密码管理器 | 开启同步时通常会，端到端加密。Windows Hello 的钥匙只留在这台电脑上 |
| **另一部手机**，扫二维码连接 | 那部手机的密码管理器 | 同上 |
| **硬件安全密钥**（YubiKey 等 FIDO2 密钥，USB 或 NFC） | 安全密钥内部 | 永远不会 |

一个 Vela 钱包最多可以用七把钥匙，种类可以任意搭配，在创建时选定；
[签名钥匙与安全密钥](/zh/docs/signers)讲的就是怎么选。

## 为什么没有东西可钓

钓鱼靠的是骗你交出一个秘密。助记词是十二个单词，你可能被说服把它输进某个地方。通行密钥
**没有可以输入的秘密**：没什么可泄露、可粘贴，假网站也无从索要。而且通行密钥只属于一个
网站，你的设备不会把 `getvela.app` 的通行密钥用在任何别的域名的页面上。

这就消除了自托管里一类常见的损失——恢复短语被盗。

## 通行密钥防不了什么

<Callout type="warning" title="你批准什么，通行密钥就签什么">
手机或浏览器弹出的提示只告诉你用的是<em>哪一把</em>钥匙，并不显示签的是<em>什么</em>。
只要你批准，通行密钥对有害交易和正常交易一视同仁。这就是为什么 Vela 在你签名前会解码每一笔
交易（<a href="/zh/docs/clear-signing">清晰签名</a>），也是为什么显示交易的那个页面本身很重要
（<a href="/zh/docs/bybit-attack">Bybit 事件</a>）。
</Callout>

它也防不了拿到你已解锁的手机、并能通过手机验证的人，或是控制了你通行密钥同步账号的人。
请设置设备密码，保护好你的 Apple 或 Google 账号，也可以考虑一把哪里都不同步的硬件安全密钥。

## 签名是什么感觉

1. 看清交易内容后，你在 Vela 里确认。
2. 设备或安全密钥要求面容、指纹、PIN，或触碰一下。
3. 它完成签名，只有签名被送回 App。
4. App 把签好的操作交给中继提交；你的钱包合约先在链上验证通行密钥签名，再执行任何操作。

## 公钥去了哪里

你的钥匙的**公钥**部分记录在 Gnosis 链上的一个公开注册表里，这样新设备才能找到你的钱包。
这是[恢复与登录](/zh/docs/recovery)要讲的内容。
