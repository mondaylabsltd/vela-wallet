# 网络与费用

## 支持的网络

Vela 内置 **12 条 EVM 网络**：

| 网络 | 原生手续费代币 |
| ----------- | ---------------- |
| 以太坊 | ETH |
| BNB Chain | BNB |
| Polygon | POL |
| Arbitrum | ETH |
| Optimism | ETH |
| Base | ETH |
| Avalanche | AVAX |
| Gnosis | xDAI |
| Unichain | ETH |
| Tempo | USD |
| Monad | MON |
| World Chain | ETH |

你的钱包**在所有这些网络上都是同一个地址**，所以到处给同一个地址就行。

你也可以**添加自定义网络**（设置 → 网络）。因为 Vela 是智能账户钱包，所以一条网络
必须提供 Vela 依赖的那些合约——ERC-4337 EntryPoint、Safe 合约，以及在链上验证你
通行密钥的 **P-256（RIP-7212）**签名预编译。在允许你添加一条网络之前，Vela 会
自动检查这些。

<Callout type="info" title="为什么 Gnosis 出现得特别多">
除了是这 12 条网络之一，Gnosis Chain 还承载着 Vela 的**通行密钥索引**——那个为了
跨设备恢复而保存你公钥和账户名字的合约。它和你在哪条网络上交易是两回事。
</Callout>

## 费用是怎么算的（账户抽象）

Vela 使用 **ERC-4337 账户抽象**，所以一笔交易不是由你直接广播的——它是一个
**UserOperation**，交给一个**中继**，由它提交上链并拿回 gas 的补偿。（ERC-4337
规范把这个角色叫作 *bundler*。Vela 这一份叫中继，是因为它做的不止是打包：它
带内报价，还运行下面那套 gas 账户协议，这两件事都不在标准里。）由此引出几件事：

- **gas 从你自己钱包的余额里付**——默认用该网络的原生代币（ETH、BNB、xDAI……），
  或者在中继提供支持的地方用某种稳定币；费用资产在确认页上由你选。Tempo 没有原生币，
  所以那里的 gas 一律用美元稳定币结算。这里没有 ERC-4337 的 **paymaster** 来赞助——
  或者卡住——每一笔交易。（Vela 可能会为新用户赞助那次一次性的 *gas 账户激活*；
  那是另一回事，下面会讲。）
- **gas 价格由中继报出**——它是唯一的事实来源，钱包显示这份报价，并且签的就是它
  显示的东西。这里没有速度选择器：每一笔交易都以高优先级提交。
- 总费用是**网络成本加上中继的服务费**，非常便宜的交易会有一个很小的最低收费。
  中继的报价就是价格——不存在另一份要去查的费率表。其中一部分归这条链的验证者；
  剩下的付给那个垫付 gas、并且运行这套基础设施的中继方。
- 确认页在你签名前，会用费用资产和你的显示货币两种形式展示**预估费用**。报出的
  金额和它的收款方都是你所签内容的一部分，所以中继拿到的分文不差就是显示过的那个数
  ——数字一改，你的签名就失效了。

## 谁在运行中继——费用又归谁

每一条网络都指向一个中继。默认是 **Vela 自己的中继**，你可以在
*设置 → 高级 → 服务端点* 里替换这个地址。一个端点对所有内置网络生效；自定义网络
则沿用你添加它时填的那个中继地址。

关于兼容性有一条老实话：应用是通过一个 Vela 专有的 RPC 方法
（`vela_getInBandGasQuote`）来获取费用报价的，没有它，发送流程就走不下去。所以
你指过去的那个端点必须跑着
[vela-relay](https://github.com/mondaylabsltd/vela-relay)——Vela 的实例，或者你
自己托管的一份。像 **Pimlico** 或 **Alchemy** 这样的通用 ERC-4337 bundler 没有实现
这个方法，所以在当前版本里没法端到端跑通。

谁在为一条网络运行中继，**谁就收走那条网络上的费用**——每笔交易的中继加价，
以及 gas 账户的激活押金。自己跑一份 vela-relay，这些费用就去养你自己的基础设施，
而不是 Vela 的；你路由到别处的流量，Vela 不抽一分。

<Callout type="warning" title="gas 账户是 vela-relay 协议的一部分">
**gas 账户激活**这一步，是在每条网络上为你的钱包出资建立一个专属的中继账户。
如果你把端点指向自己托管的 vela-relay，这笔押金进的是你自己中继的账户，不是 Vela 的。
</Callout>

### 激活 gas 账户（Vela Relay）

在 Vela 的中继上，你在每条网络上的第一笔交易会**激活一个专属的 gas 账户**。应用会
先请求中继的资金池替你出这笔钱——这一步在发送流程里悄悄完成，被赞助到的钱包
根本不会看到什么出资界面。只有当赞助被拒绝时，应用才会显示一个充值请求：你往它
显示的那个 gas 账户地址转一小笔原生代币，同时它会告诉你为什么这次没有赞助。

**在拿不到免费赞助时，激活费由你自己付**——也就是下面这些情况：

- **Vela 在那条网络上的资金池空了或者快空了** —— 那条链上的免费额度暂时用尽。
- **你把免费额度用完了** —— 赞助是按钱包封顶的，超出前几次之后就自费。
- **Vela 的中继根本不为那条网络出资** —— 比如**你自己添加的自定义网络或测试网**，
  Vela 在上面没有任何资金池。（如果你宁愿完全跳过激活，就把它们路由到你自己的中继。）

这笔激活押金**不可退还**——它是中继账户的启动余额，之后会从 gas 返还里慢慢补回来，
不过它仍然可能被耗尽，之后需要**重新激活**。服务升级时中继地址也可能变更，那也需要
重新激活一次。

费用从你所选的**费用资产**余额里扣——默认是原生代币。如果一次发送因为 gas 被拦下，
说明你那个费用资产的余额不够付费用；在中继提供稳定币 gas 的地方，在确认页上换一种
费用资产就能解开。

当你发送某种原生代币的**最大金额**时，Vela 会自动预留足够的 gas，好让交易不至于失败。

## Vela 怎么跟每条网络打交道

Vela 读取余额和提交交易走的是**一组 RPC 节点**，而不是单一服务商。它从多个来源
收集节点，按延迟和可靠性打分，并在某个节点慢了或者挂了时**自动切换**——把坏节点
暂时冷藏——这样单个不稳定的节点永远不会让整个应用下线。
