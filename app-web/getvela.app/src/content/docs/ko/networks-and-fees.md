# 네트워크와 수수료

## 지원 네트워크

Vela에는 **12개 EVM 네트워크**가 내장되어 있습니다.

| 네트워크 | 네이티브 수수료 토큰 |
| ----------- | ---------------- |
| 이더리움 | ETH |
| BNB 체인 | BNB |
| 폴리곤 | POL |
| 아비트럼 | ETH |
| 옵티미즘 | ETH |
| 베이스 | ETH |
| 아발란체 | AVAX |
| Gnosis | xDAI |
| Unichain | ETH |
| Tempo | USD |
| Monad | MON |
| World Chain | ETH |

당신의 지갑은 **이 모두에서 같은 주소**이므로, 어디서든 건넬 주소는 하나입니다.

**커스텀 네트워크 추가**도 됩니다(설정 → 네트워크). Vela는 스마트 계정 지갑이므로,
네트워크에는 Vela가 의존하는 컨트랙트가 있어야 합니다 — ERC-4337 EntryPoint, Safe
컨트랙트, 그리고 패스키를 온체인에서 검증하는 **P-256(RIP-7212)** 프리컴파일입니다.
추가를 허용하기 전에 Vela가 자동으로 확인합니다.

<Callout type="info" title="Gnosis가 자주 나오는 이유">
12개 네트워크 중 하나라는 점 외에, Gnosis 체인은 Vela의 **패스키 인덱스** — 기기 간
복구를 위해 공개 키와 계정 이름을 저장하는 컨트랙트 — 를 올려 두고 있습니다. 어떤
네트워크에서 거래하느냐와는 별개의 이야기입니다.
</Callout>

## 수수료가 매겨지는 방식(계정 추상화)

Vela는 **ERC-4337 계정 추상화**를 쓰므로, 거래를 당신이 직접 브로드캐스트하지 않고
**UserOperation**으로 **릴레이**에 넘기면, 릴레이가 온체인에 제출하고 가스를 정산받
습니다. (ERC-4337 명세는 이 역할을 *bundler*라고 부릅니다. Vela의 것을 릴레이라고
부르는 이유는 묶는 일 이상을 하기 때문입니다. 수수료를 인밴드로 제시하고, 아래의 가스
계정 프로토콜을 운영합니다. 둘 다 표준의 일부가 아닙니다.) 여기서 몇 가지가 따라옵니다.

- **가스는 당신 지갑의 잔액에서 나갑니다** — 기본은 네트워크의 네이티브 토큰
  (ETH, BNB, xDAI…)이고, 릴레이가 지원하면 스테이블코인으로도 됩니다. 수수료 자산은
  확인 화면에서 고릅니다. 네이티브 코인이 없는 Tempo에서는 가스가 항상 USD
  스테이블코인으로 정산됩니다. 거래마다 후원하거나 — 혹은 막는 — ERC-4337의
  **paymaster**는 없습니다. (신규 사용자의 일회성 *가스 계정 활성화*를 Vela가 대신
  내 주는 경우는 있습니다. 그건 별개이고 아래에서 다룹니다.)
- **가스 가격을 제시하는 것은 릴레이**이고, 그것이 유일한 기준입니다. 지갑은 그
  제시를 표시하고, 표시한 그대로에 서명합니다. 속도 선택지는 없습니다. 모든 거래가
  높은 우선순위로 제출됩니다.
- 총액은 **네트워크 비용에 릴레이의 서비스 수수료를 더한 것**이고, 아주 싼 거래에는
  작은 최소 금액이 붙습니다. 릴레이의 제시가 곧 가격이고, 따로 찾아볼 요금표는
  없습니다. 일부는 체인의 검증자에게, 나머지는 가스를 먼저 내고 인프라를 운영하는
  릴레이에 갑니다.
- 확인 화면은 서명 전에 **예상 수수료**를 수수료 자산과 표시 통화로 보여 줍니다.
  제시된 금액과 그 수취처는 당신이 서명하는 내용의 일부이므로, 릴레이가 받는 것은
  정확히 표시된 금액입니다. 숫자가 바뀌면 서명이 무효가 됩니다.

## 릴레이는 누가 운영하고, 수수료는 누구의 것인가

모든 네트워크는 릴레이를 가리킵니다. 기본값은 **Vela 자체 릴레이**이고,
*설정 → 고급 → 서비스 엔드포인트*에서 바꿀 수 있습니다. 엔드포인트 하나가 모든 내장
네트워크에 적용되며, 커스텀 네트워크는 추가할 때 지정한 릴레이 URL을 유지합니다.

호환성에 대한 솔직한 단서: 앱은 Vela 고유의 RPC 메서드
(`vela_getInBandGasQuote`)로 수수료를 받아 오고, 그것이 없으면 보내기 흐름이
진행되지 않습니다. 그러니 가리키는 엔드포인트는
[vela-relay](https://github.com/mondaylabsltd/vela-relay)를 돌리고 있어야 합니다 —
Vela의 인스턴스이거나, 당신이 직접 세운 것이거나. **Pimlico**나 **Alchemy** 같은
일반 ERC-4337 bundler는 그 메서드를 구현하지 않으므로, 현재 릴리스에서는 끝까지
동작하지 않습니다.

어떤 네트워크에서 릴레이를 운영하는 쪽이 **그 네트워크의 수수료를 가져갑니다** —
거래마다 붙는 릴레이 마진과 가스 계정 활성화 보증금입니다. vela-relay를 직접 돌리면
그 수수료는 Vela가 아니라 당신의 인프라를 지탱합니다. 다른 곳으로 보낸 트래픽에서
Vela가 가져가는 몫은 없습니다.

<Callout type="warning" title="가스 계정은 vela-relay 프로토콜의 일부입니다">
**가스 계정 활성화**는 각 네트워크에서 당신 지갑 전용의 릴레이 계정에 자금을 넣는
단계입니다. 엔드포인트를 직접 운영하는 vela-relay로 돌렸다면, 그 보증금은 Vela가
아니라 당신 릴레이의 계정으로 들어갑니다.
</Callout>

### 가스 계정 활성화하기(Vela Relay)

Vela의 릴레이에서는 각 네트워크의 첫 거래가 **전용 가스 계정을 활성화**합니다. 앱은
먼저 릴레이의 재원에 대납을 요청합니다. 이 과정은 보내기 흐름 안에서 조용히 일어나고,
대납을 받은 지갑은 자금 투입 화면을 보지 않습니다. 거절되었을 때만 앱이 충전 요청을
보여 줍니다. 표시된 가스 계정 주소로 네이티브 토큰을 조금 보내는 방식이고, 왜 이번에
대납이 안 됐는지도 함께 알려 줍니다.

**무료 대납이 제공되지 않을 때 활성화 비용은 당신이 냅니다.** 구체적으로는:

- **그 네트워크의 Vela 재원이 비었거나 적을 때** — 해당 체인의 무료 재원이 일시적으로
  소진된 경우입니다.
- **무료 한도를 다 썼을 때** — 대납은 지갑당 상한이 있어, 처음 몇 번을 넘기면
  자부담입니다.
- **Vela의 릴레이가 그 네트워크에 아예 자금을 대지 않을 때** — 예를 들어 **직접 추가한
  커스텀 네트워크나 테스트넷**으로, Vela는 거기에 재원을 두지 않습니다. (활성화 자체를
  건너뛰고 싶다면 자신의 릴레이로 보내세요.)

이 활성화 보증금은 **환불되지 않습니다.** 릴레이 계정의 시작 잔액이고, 시간이 지나며
가스 정산으로 스스로 채워지지만, 그래도 바닥나 **재활성화**가 필요할 수 있습니다.
서비스 업그레이드로 릴레이 주소가 바뀌면 그때도 새로 활성화해야 합니다.

비용은 당신이 고른 **수수료 자산**의 잔액에서 나갑니다(기본은 네이티브 토큰).
가스 때문에 보내기가 막힌다면, 그 수수료 자산의 잔액이 비용에 못 미친다는 뜻입니다.
릴레이가 스테이블코인 가스를 제공하는 곳이라면, 확인 화면에서 수수료 자산을 바꾸면
풀릴 수 있습니다.

네이티브 토큰을 **최대 금액**으로 보낼 때는, 거래가 실패하지 않도록 Vela가 가스를
자동으로 남겨 둡니다.

## Vela는 각 네트워크와 어떻게 통신하나

Vela는 잔액을 읽고 거래를 제출할 때 단일 공급자가 아니라 **RPC 엔드포인트 풀**을
씁니다. 여러 출처에서 엔드포인트를 모으고, 지연과 신뢰도로 점수를 매기며, 느리거나
죽은 것은 **자동으로 우회**합니다. 나쁜 엔드포인트는 잠시 제외되므로, 불안정한 노드
하나가 앱 전체를 멈추는 일은 없습니다.
