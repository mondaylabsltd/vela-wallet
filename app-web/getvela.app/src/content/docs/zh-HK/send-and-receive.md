# 轉帳同收款

## 收款

1. 打開個錢包，撳**收款**。
2. 將地址畀出去——複製佢，或者畀對方掃 QR Code。
3. 轉帳喺鏈上確認之後，餘額就會出現喺你個錢包度。

有兩樣嘢值得知：

- 你個地址**喺每一條支援嘅網絡上面都一樣**，所以去邊都畀同一個地址就得——
  只要確認對方用啱網絡。
- 你**喺錢包合約部署之前就收得錢**。Vela 嘅帳戶係反事實智能帳戶，所以喺某條鏈上
  合約仲未存在嗰陣，錢已經入得到你個地址；等你第一次喺嗰條鏈發交易嗰時，
  佢會將自己部署上去。

## 轉帳

1. 撳**轉帳**，揀**代幣**。
2. 輸入**金額**（可以喺代幣同你嘅顯示貨幣之間切換）同**收款方**。只要認得出，
   Vela 會將已知嘅收款方顯示成名——一個 Vela 帳戶、一個 ENS 名、一個 Basename
   等等。
3. **核對同確認。** Vela 將呢筆轉帳擺出嚟畀你睇，然後叫你用通行密鑰
   （Face ID / Touch ID / 指紋）確認。

### 你撳完確認之後發生咗啲乜

Vela 唔係淨係將交易「廣播」出去。底層係咁：

1. 佢為你個 Safe 帳戶砌咗一個 ERC-4337 **UserOperation**。
2. 你部機喺生物認證之後，用一次 **WebAuthn（P-256）**斷言幫佢簽名。
3. 簽好嘅操作送去**中繼**，由佢提交畀 EntryPoint；你個 Safe 喺**鏈上**驗證
   呢個 P-256 簽名，然後執行。

<Callout type="info" title="中繼郁唔到你嘅交易">
中繼收到嘅係一份<strong>已經簽咗名</strong>嘅 UserOperation。佢可以拖，亦可以
拒絕轉發，但改唔到收款方、金額或者任何其他欄位——一改，你個簽名就失效。
佢係一個幫你上鏈嘅角色，唔係保管方，而且佢開源，你可以自己行一個。
</Callout>

### 清晰簽署——唔做盲簽

喺你簽名之前，Vela 會用 **ERC-7730** 描述符解碼呢筆交易，顯示佢嘅**意圖**
（轉帳、授權、兌換……）、**金額同地址**，同埋一個風險提示——而唔係一串睇唔明嘅
十六進制。當佢解唔晒一個調用嗰陣，佢會出一個明確嘅**盲簽警告**，而唔係扮自己睇得明。
無限額度嘅代幣授權唔止俾人標記——Vela 會將佢改寫成一個有限嘅金額，並且拒絕提交
任何仲係無限嘅授權。

## 撳送出之前

- **核對地址頭尾幾個字元。** 會換地址嘅惡意軟件係真係存在。
- **確認網絡。** 送錯網絡係最常見、亦最貴嗰個失誤。睇[網絡同費用](/zh-HK/docs/networks-and-fees)。
- **對新收款方先細額試一次。** 先轉一筆好細嘅錢，係好平嘅保險。

交易冇得反悔。轉錯地址之後，冇任何客服可以幫你追返——呢個就係自我保管嘅本質。

## 點睇歷史紀錄

餘額同歷史紀錄係由一組公開 RPC 節點即時讀取嘅，而且會自動容錯切換。如果網絡慢，
歷史可能要等一陣——轉圈嘅意思係「仲喺度攞」，唔係「啲錢冇咗」。
