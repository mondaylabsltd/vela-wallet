# 網絡同費用

## 支援嘅網絡

Vela 內置 **12 條 EVM 網絡**：

| 網絡 | 原生手續費代幣 |
| ----------- | ---------------- |
| 以太坊 | ETH |
| BNB Chain | BNB |
| Polygon | POL |
| Arbitrum | ETH |
| Optimism | ETH |
| Base | ETH |
| Avalanche | AVAX |
| Gnosis | xDAI |
| Unichain | ETH |
| Tempo | USD |
| Monad | MON |
| World Chain | ETH |

你個錢包**喺所有呢啲網絡上面都係同一個地址**，所以去邊都畀同一個地址就得。

你亦可以**加自訂網絡**（設定 → 網絡）。因為 Vela 係智能帳戶錢包，所以一條網絡
必須提供 Vela 依賴嘅嗰啲合約——ERC-4337 EntryPoint、Safe 合約，以及喺鏈上驗證你
通行密鑰嘅 **P-256（RIP-7212）**簽名預編譯。喺容許你加一條網絡之前，Vela 會自動
檢查呢啲。

<Callout type="info" title="點解 Gnosis 出現得特別多">
除咗係呢 12 條網絡之一，Gnosis Chain 仲載住 Vela 嘅**通行密鑰索引**——嗰份為咗
跨裝置復原而保存你公鑰同帳戶名嘅合約。佢同你喺邊條網絡交易係兩回事。
</Callout>

## 費用點計（帳戶抽象）

Vela 用 **ERC-4337 帳戶抽象**，所以一筆交易唔係你直接廣播嘅——佢係一個
**UserOperation**，交畀一個**中繼**，由佢提交上鏈並攞返 gas 嘅補償。（ERC-4337
規範叫呢個角色做 *bundler*。Vela 呢一份叫中繼，係因為佢做嘅唔止係打包：佢帶內報價，
仲行住下面嗰套 gas 帳戶協定，呢兩樣都唔喺標準入面。）由此帶出幾樣嘢：

- **gas 由你自己個錢包餘額度畀**——預設用嗰條網絡嘅原生代幣（ETH、BNB、xDAI……），
  或者喺中繼有支援嘅地方用某種穩定幣；費用資產喺確認頁上面由你揀。Tempo 冇原生幣，
  所以嗰度嘅 gas 一律用美元穩定幣結算。呢度冇 ERC-4337 嘅 **paymaster** 去贊助——
  又或者卡住——每一筆交易。（Vela 可能會為新用戶贊助嗰次一次性嘅 *gas 帳戶啟用*；
  嗰個係另一回事，下面會講。）
- **gas 價格由中繼報出**——佢係唯一嘅事實來源，錢包顯示呢份報價，而且簽嘅就係佢
  顯示嗰樣嘢。呢度冇速度選擇器：每一筆交易都以高優先度提交。
- 總費用係**網絡成本加中繼嘅服務費**，好平嘅交易會有一個好細嘅最低收費。
  中繼嘅報價就係價錢——冇另一份要去查嘅收費表。其中一部分歸嗰條鏈嘅驗證者；
  其餘畀嗰個墊住 gas、又維運呢套基礎設施嘅中繼方。
- 確認頁喺你簽名前，會用費用資產同你嘅顯示貨幣兩種形式顯示**預估費用**。報出嘅
  金額同佢個收款方都係你所簽內容嘅一部分，所以中繼收到嘅一蚊都唔多唔少，就係顯示過
  嗰個數——一改個數，你個簽名就失效。

## 邊個行中繼——啲費用又歸邊個

每一條網絡都指向一個中繼。預設係 **Vela 自己嘅中繼**，你可以喺
*設定 → 進階 → 服務端點* 度換呢個地址。一個端點對所有內置網絡生效；自訂網絡
就沿用你加佢嗰陣填嘅中繼地址。

關於相容性有一句老實話：應用係經一個 Vela 專屬嘅 RPC 方法
（`vela_getInBandGasQuote`）攞費用報價嘅，冇咗佢，轉帳流程就行唔落去。所以你指過去
嗰個端點必須行緊
[vela-relay](https://github.com/mondaylabsltd/vela-relay)——Vela 嘅實例，或者你
自己架嘅一份。好似 **Pimlico** 或者 **Alchemy** 嗰類通用 ERC-4337 bundler 冇實作
呢個方法，所以喺目前版本度行唔通成條路。

邊個為一條網絡行中繼，**邊個就收走嗰條網絡嘅費用**——每筆交易嘅中繼加價，
以及 gas 帳戶嘅啟用按金。自己行一份 vela-relay，呢啲費用就去養你自己嘅基礎設施，
而唔係 Vela 嘅；你導去第度嘅流量，Vela 一蚊都唔抽。

<Callout type="warning" title="gas 帳戶係 vela-relay 協定嘅一部分">
**gas 帳戶啟用**呢一步，係喺每條網絡上面為你個錢包出錢開一個專屬嘅中繼帳戶。
如果你將端點指向自己架嘅 vela-relay，呢筆按金入嘅係你自己中繼嘅帳戶，唔係 Vela 嘅。
</Callout>

### 啟用 gas 帳戶（Vela Relay）

喺 Vela 嘅中繼上面，你喺每條網絡嘅第一筆交易會**啟用一個專屬嘅 gas 帳戶**。應用會
先請中繼嘅資金池幫你出呢筆錢——呢一步喺轉帳流程裡面靜靜雞完成，俾人贊助到嘅錢包
根本唔會見到任何出資畫面。淨係當贊助俾人拒絕嗰陣，應用先會顯示一個充值請求：你向佢
顯示嗰個 gas 帳戶地址轉一筆好細嘅原生代幣，同時佢會話你知點解今次冇贊助。

**攞唔到免費贊助嗰陣，啟用費由你自己畀**——即係下面呢啲情況：

- **Vela 喺嗰條網絡嘅資金池空咗或者快空** —— 嗰條鏈上面嘅免費額度暫時用晒。
- **你用晒免費額度** —— 贊助係以錢包為單位封頂嘅，超過頭幾次之後就自費。
- **Vela 嘅中繼根本唔為嗰條網絡出錢** —— 例如**你自己加嘅自訂網絡或者測試網**，
  Vela 喺上面冇任何資金池。（如果你寧願完全跳過啟用，就將佢哋導去你自己嘅中繼。）

呢筆啟用按金**唔退還**——佢係中繼帳戶嘅起始餘額，之後會由 gas 退款度慢慢補返，
不過佢仍然可能用完，之後需要**重新啟用**。服務升級嗰陣中繼地址亦可能變，嗰種情況
都要重新啟用一次。

費用由你揀嘅**費用資產**餘額扣——預設係原生代幣。如果一次轉帳因為 gas 被擋低，
即係話你嗰個費用資產嘅餘額唔夠畀費用；喺中繼有提供穩定幣 gas 嘅地方，喺確認頁度
換一種費用資產就解得開。

當你轉走某種原生代幣嘅**最大金額**嗰陣，Vela 會自動預留夠嘅 gas，等交易唔會失敗。

## Vela 點同每條網絡打交道

Vela 讀餘額同提交交易行嘅係**一組 RPC 節點**，而唔係單一供應商。佢由幾個來源收集
節點，按延遲同可靠度評分，並喺某個節點慢咗或者掛咗嗰陣**自動切換**——將壞節點暫時
雪藏——咁樣單一個唔穩定嘅節點永遠唔會令成個應用落線。
