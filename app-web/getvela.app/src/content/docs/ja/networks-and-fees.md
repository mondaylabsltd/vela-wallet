# ネットワークと手数料

## 対応ネットワーク

Vela には **12 の EVM ネットワーク**が組み込まれています。

| ネットワーク | ネイティブの手数料トークン |
| ----------- | ---------------- |
| Ethereum | ETH |
| BNB Chain | BNB |
| Polygon | POL |
| Arbitrum | ETH |
| Optimism | ETH |
| Base | ETH |
| Avalanche | AVAX |
| Gnosis | xDAI |
| Unichain | ETH |
| Tempo | USD |
| Monad | MON |
| World Chain | ETH |

あなたのウォレットは**すべてで同じアドレス**なので、どこにでも渡すアドレスはひとつ
です。

**カスタムネットワークの追加**もできます（設定 → ネットワーク）。Vela はスマート
アカウントのウォレットなので、そのネットワークには Vela が依存するコントラクトが
必要です——ERC-4337 の EntryPoint、Safe のコントラクト、そしてパスキーをオンチェーン
で検証する **P-256（RIP-7212）**のプリコンパイルです。追加を許可する前に、Vela が
自動で確認します。

<Callout type="info" title="Gnosis がよく出てくる理由">
12 のネットワークのひとつであることに加え、Gnosis Chain は Vela の**パスキー
インデックス**——端末をまたぐ復旧のために公開鍵とアカウント名を保存するコントラクト
——を載せています。どのネットワークで取引するかとは別の話です。
</Callout>

## 手数料のしくみ（アカウント抽象化）

Vela は **ERC-4337 のアカウント抽象化**を使うので、取引はあなたが直接ブロード
キャストするのではなく、**UserOperation** として**リレー**に渡され、リレーがそれを
オンチェーンに提出してガスの精算を受けます。（ERC-4337 の仕様ではこの役割を
*bundler* と呼びます。Vela のものをリレーと呼ぶのは、束ねる以上のことをするから
です。手数料をインバンドで提示し、下に書くガスアカウントのプロトコルを動かします。
どちらも標準の一部ではありません。）そこから、いくつかのことが導かれます。

- **ガスはあなた自身のウォレット残高から支払われます**——既定ではそのネットワークの
  ネイティブトークン（ETH、BNB、xDAI…）で、リレーが対応している場合はステーブル
  コインでも。手数料の資産は確認画面で選べます。Tempo にはネイティブコインがないので、
  ガスは常に USD ステーブルコインで決済されます。取引ごとにスポンサーする——あるいは
  ゲートする—— ERC-4337 の **paymaster** はありません。（新規ユーザーの一度きりの
  *ガスアカウント有効化*を Vela が肩代わりすることはあります。それは別の話で、
  下で説明します。）
- **ガス価格を提示するのはリレー**であり、それが唯一の情報源です。ウォレットはその
  提示を表示し、表示したとおりのものに署名します。速度の選択肢はありません。すべての
  取引が高い優先度で提出されます。
- 合計は**ネットワークの費用にリレーのサービス手数料を足したもの**で、とても安い
  取引には小さな最低額があります。リレーの提示がそのまま価格であり、別に参照すべき
  料金表はありません。一部はチェーンのバリデーターへ、残りはガスを立て替え、基盤を
  運用するリレーへ渡ります。
- 確認画面は、署名の前に**見積もり手数料**を手数料資産と表示通貨の両方で示します。
  提示額とその受取先はあなたが署名する内容の一部なので、リレーが受け取るのは表示
  されたとおりの額です。数字が変われば署名が無効になります。

## リレーを動かすのは誰で、手数料は誰のものか

どのネットワークもリレーを指しています。既定では **Vela 自身のリレー**で、
*設定 → 詳細 → サービスエンドポイント*で差し替えられます。ひとつのエンドポイントが
すべての組み込みネットワークに適用され、カスタムネットワークは追加時に指定した
リレーの URL を保ちます。

互換性についての正直な注意点：アプリは Vela 固有の RPC メソッド
（`vela_getInBandGasQuote`）で手数料を取得しており、それがないと送金のフローは進み
ません。つまり、指すエンドポイントは
[vela-relay](https://github.com/mondaylabsltd/vela-relay) を動かしている必要が
あります——Vela のインスタンスか、あなたが自分で立てたものです。**Pimlico** や
**Alchemy** のような一般的な ERC-4337 bundler はそのメソッドを実装していないので、
現行リリースでは最後まで動きません。

あるネットワークでリレーを運用する者が、**そのネットワークの手数料を受け取ります**
——各取引のリレーのマークアップと、ガスアカウントの有効化デポジットです。自分で
vela-relay を動かせば、その手数料は Vela ではなくあなたの基盤を支えます。他所へ
流したトラフィックから Vela が取る分はありません。

<Callout type="warning" title="ガスアカウントは vela-relay のプロトコルの一部です">
**ガスアカウントの有効化**は、各ネットワークであなたのウォレット専用のリレー用
アカウントに資金を入れる手順です。エンドポイントを自前の vela-relay に向けているなら、
そのデポジットは Vela ではなく、あなたのリレーのアカウントに入ります。
</Callout>

### ガスアカウントを有効化する（Vela Relay）

Vela のリレーでは、各ネットワークでの最初の取引が**専用のガスアカウントを有効化**
します。アプリはまずリレーのトレジャリーに肩代わりを依頼します。これは送金フローの
中で静かに行われ、肩代わりされたウォレットが資金投入の画面を見ることはありません。
断られたときだけ、アプリがチャージの依頼を表示します。表示されたガスアカウントの
アドレスへネイティブトークンを少額送る形で、なぜ肩代わりされなかったのかも示されます。

**無料の肩代わりが提供されないとき、有効化の費用はあなたが払います。** 具体的には：

- **そのネットワークの Vela のトレジャリーが空か少ないとき** —— そのチェーンで無料
  の原資が一時的に尽きています。
- **無料枠を使い切ったとき** —— 肩代わりはウォレットごとに上限があるので、最初の
  数回を超えると自己負担になります。
- **Vela のリレーがそのネットワークに一切資金を出していないとき** —— たとえば
  **自分で追加したカスタムネットワークやテストネット**で、Vela はそこにトレジャリー
  を持ちません。（有効化そのものを避けたいなら、自前のリレーへ向けてください。）

この有効化デポジットは**返金されません**。リレーアカウントの初期残高であり、時間と
ともにガスの精算から自分で積み増されますが、それでも減りきって**再有効化**が必要に
なることがあります。サービス更新でリレーのアドレスが変わると、その場合も新たな
有効化が必要です。

費用は、あなたが選んだ**手数料資産**の残高から引かれます（既定はネイティブトークン）。
ガス不足で送金が止まるのは、その手数料資産の残高が費用に足りないということです。
リレーがステーブルコインのガスを提供している場合は、確認画面で手数料資産を切り替える
と解消できることがあります。

ネイティブトークンを**全額**送るときは、取引が失敗しないように、Vela が自動でガス分
を取り置きます。

## Vela は各ネットワークとどう話すか

Vela は残高の取得も取引の提出も、単一のプロバイダーではなく **RPC エンドポイントの
プール**を通して行います。複数の情報源からエンドポイントを集め、遅延と信頼性で
スコア付けし、遅いものや落ちたものからは**自動でフェイルオーバー**します。悪い
エンドポイントは一時的に外されるので、不安定なノードひとつでアプリ全体が止まることは
ありません。
