# アカウントコントラクト

あなたのウォレットは、アプリの中だけにあるデータ構造ではありません。**Safe v1.4.1** のスマートアカウントです。オンチェーンの大規模なトレジャリーの多くが使っているのと同じコントラクトで、Safe が公開しているとおりに、一切改変せずにデプロイしています。

## 経路上に私たちのものはない

資金に触れうるコントラクトは、すべて Safe か ERC-4337 の作者たちが書いたものです。

| コントラクト | ウォレットでの役割 | 作者 |
| --- | --- | --- |
| [Safe v1.4.1](https://github.com/safe-fndn/safe-smart-account/tree/v1.4.1)（SafeL2、プロキシ経由） | アカウント本体。所有者、しきい値、実行 | Safe |
| [Safe 4337 Module v0.3.0](https://github.com/safe-global/safe-modules/tree/4337/v0.3.0/modules/4337) | EntryPoint が Safe を操作できるようにする。フォールバックハンドラーも兼ねる | Safe |
| [SafeWebAuthnSharedSigner v0.2.1](https://github.com/safe-global/safe-modules/tree/passkey/v0.2.1/modules/passkey) | 最初の鍵の P-256 署名を検証する | Safe |
| [SafeWebAuthnSignerFactory v0.2.1](https://github.com/safe-global/safe-modules/tree/passkey/v0.2.1/modules/passkey) と、それが作成する署名器 | 追加の鍵 1 本ごとに、小さな署名器コントラクトを 1 つ | Safe |
| [ERC-4337 EntryPoint v0.7](https://github.com/eth-infinitism/account-abstraction/releases/tag/v0.7.0) | 署名済みの操作を実行する | ERC-4337 の作者たち |

Vela 自身のコントラクトはこの表にありません。新しい端末がウォレットを見つけられるように各ウォレットの鍵を記録する**公開鍵レジストリ**（[復旧](/ja/docs/recovery)）、それと対になるドメインレジストリ、そしてそれらが置き換えた以前のインデックスです。これらは資金を持たず、あなたの Safe での役割もありません。

ウォレットのリポジトリには Solidity が一切含まれていません。コマンドひとつで確かめられます。

```bash
git clone https://github.com/mondaylabsltd/vela-wallet
find vela-wallet -name '*.sol'   # 何も表示されない
```

Vela はあなたのアカウントに対して特権的な権限を持ちません。管理者鍵も、アップグレードの経路も、Vela が追加できるモジュールもありません。あなたの Safe を変更できるのは、あなたの鍵だけです。

## 「改変していない」ことが重要な理由

「Safe」をベースにした、Safe をフォークした、あるいは Safe に着想を得たアカウントの上に作られたウォレットはたくさんあります。その違いは 3 つの点で効いてきます。

**監査が、実際に使っているものに当てはまります。**Safe の監査は、これらのリリース、またはそれと小さな文書化された変更だけが異なる以前のリリースを対象にしています（詳細は[監査のページ](/ja/docs/security-audits)）。フォークの監査が対象にしているのはフォーク前のコードであり、手を加えた部分は誰も監査していません。

**エコシステムがあなたのアカウントを Safe として扱います。実際に Safe だからです。**ブロックエクスプローラーはこれをデコードし、Safe のツールはこれを読み取り、そのための取引を組み立てられます。ただし、その取引に*署名*するには、パスキーが属するドメインである `getvela.app` 向けの署名をあなたの鍵に求められるプログラムが必要です。そのため、別のドメインから配信されている Safe 自身のウェブアプリでは、あなたの代わりに署名できません。何なら署名できるかは[セルフホスティングガイド](/ja/docs/self-hosting#if-getvela-app-disappears)にまとめています。

**攻撃面を、ほかの多くの人も見張っています。**独自のアカウントコントラクトを見張っているのは、たいていその作者だけです。Safe のコアコントラクトは、Safe に資金を置いている全員が見張っています。4337 モジュールとパスキーモジュールを見ている人はそれより少ないものの、確かにいます。

## 支払うもの

標準であることには、代償もあります。

- **ガス。**署名はオンチェーンで検証され、取引は EntryPoint を通って実行されます。私たちが Gnosis で測定したところ（2026 年 9 月）、デプロイ済みの Vela ウォレットからの単純な送金は、オンチェーンで約 14 万〜17 万ガスを使いました。通常のアカウントからの単純な ETH 送金は 21,000 ガスです。ガスに加えて、リレーが手数料を請求します。[ネットワークと手数料](/ja/docs/networks-and-fees)を参照してください。
- **アカウントのデプロイが必要。**アドレスはオンチェーンに何もないうちに `CREATE2` で計算されるので、すぐに受け取れます。各ネットワークでの最初の送金が、コントラクトのデプロイ費用を払います。
- **すべてのチェーンが条件を満たすわけではない。**パスキーの署名は **EIP-7951 / RIP-7212** プリコンパイルで検証され、そのアドレスはすべてのウォレットのセットアップデータに含まれています。そのため、プリコンパイルのないネットワークでは Vela はまったく動きません。
- **Safe のリスクが、あなたのリスクになる。**広く使われているコントラクトを信頼することも、コントラクトを信頼することに変わりはありません。Vela は、資金に至る経路上に、あなたが信頼しなければならない独自のコントラクトを追加してはいません。

## 監査済みのもの、未監査のもの

Safe のコントラクト、その 4337 モジュールとパスキーモジュール、そして EntryPoint v0.7 には、第三者による監査報告書が公開されています。**Vela 自身のコード（アプリ、バックエンドのサービス、レジストリコントラクト）は第三者による監査を受けておらず、その予定もありません。**監査は、プロジェクトが費用を賄えるようになったときの目標であり、日付の決まった約束ではありません。すべてのコントラクト、その監査報告書、私たちが追跡している問題は[監査と既知の問題](/ja/docs/security-audits)にあります。

## 自分で確かめる

あなたのアカウントはオンチェーンにあります。デプロイされたら、ブロックエクスプローラーでアドレスを開いてみてください。どのネットワークでも、実装が Safe の正規の SafeL2 v1.4.1 デプロイメントである、Safe のプロキシになっています。

次は[監査と既知の問題](/ja/docs/security-audits)。
