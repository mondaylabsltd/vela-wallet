# 送金と受取

## 受け取る

1. ウォレットを開き、**受取**をタップします。
2. アドレスを渡します——コピーするか、相手に QR コードを読み取ってもらいます。
3. 送金がオンチェーンで確定すると、残高がウォレットに現れます。

知っておくとよいことが 2 つあります。

- あなたのアドレスは**対応するどのネットワークでも同じ**なので、どこへでも同じ
  アドレスを渡せます。ただし相手が正しいネットワークを使うことは確認してください。
- **ウォレットが配置される前でも受け取れます。** Vela のアカウントはカウンター
  ファクチュアルなスマートアカウントなので、そのチェーンにコントラクトが存在しない
  うちから資金が届きます。最初の送金のときに、自分自身を配置します。

## 送る

1. **送金**をタップし、**トークン**を選びます。
2. **金額**（トークン建てと表示通貨を切り替えられます）と**受取人**を入力します。
   分かる範囲で、Vela は既知の受取人を名前に解決します——Vela のアカウント、ENS 名、
   Basename など。
3. **確認して承認。** Vela が送金内容を表示し、パスキー（Face ID / Touch ID / 指紋）
   を求めます。

### 承認した瞬間に起きていること

Vela は単に取引を「ブロードキャスト」するのではありません。内部ではこうなっています。

1. あなたの Safe アカウントのために ERC-4337 の **UserOperation** を組み立てます。
2. 生体認証のあと、端末が **WebAuthn（P-256）**のアサーションで署名します。
3. 署名済みの操作が**リレー**へ送られ、リレーがそれを EntryPoint に提出します。
   あなたの Safe が**オンチェーンで** P-256 署名を検証し、実行します。

<Callout type="info" title="リレーはあなたの取引に手を加えられません">
リレーが受け取るのは<strong>すでに署名済み</strong>の UserOperation です。遅らせる
ことも、中継を断ることもできますが、受取人も金額もその他のフィールドも変えられません
——変えればあなたの署名が無効になります。可用性のための存在であって、保管者では
ありません。オープンソースなので、自分で動かすこともできます。
</Callout>

### クリア署名——盲目的な承認をしない

署名の前に、Vela は **ERC-7730** のディスクリプタで取引をデコードし、**意図**
（送金、承認、スワップ…）、**金額とアドレス**、そしてリスクの目安を表示します。
不透明な 16 進数ではありません。呼び出しを完全にデコードできないときは、分かった
ふりをせずに明示的な**ブラインド署名の警告**を出します。無制限のトークン承認は
印を付けるだけでなく、Vela が有限の額に書き換え、それでも無制限のままの承認は
送信を拒否します。

## 送信ボタンを押す前に

- **アドレスの先頭と末尾の文字を確認する。** アドレスをすり替えるマルウェアは実在
  します。
- **ネットワークを確認する。** 間違ったネットワークへ送るのが、最もよくある高価な
  ミスです。[ネットワークと手数料](/ja/docs/networks-and-fees)を参照。
- **新しい相手にはまず少額を。** ごく小さなテスト送金は、安い保険です。

取引は取り消せません。間違ったアドレスへの送金を取り戻せる窓口はありません——それが
セルフカストディというものです。

## 履歴の読み方

残高と履歴は、公開 RPC エンドポイントのプールから自動フェイルオーバー付きでリアル
タイムに読まれます。ネットワークが遅いと履歴の表示に少し時間がかかります。回って
いるスピナーは「まだ取得中」であって、「資金が消えた」ではありません。
