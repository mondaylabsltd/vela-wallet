# Vela Wallet Web — agent notes

- **Package manager**: pnpm (this app is its own workspace; the repository
  root carries no npm state — the generators and gates are the npm package in
  `../../scripts/`, run as `npm --prefix scripts run <name>` from the root).
- **Stack**: SvelteKit 2 + Svelte 5 (runes forced), TypeScript strict,
  Cloudflare adapter (`wrangler.jsonc`), vitest (server + browser projects),
  Playwright e2e.
- **Read first**: `README.md` here, then `specs/006-web-onboarding/` at the
  repo root (plan.md, research.md, contracts/) — the architecture decisions
  (build-time wasm i18n, prerender-per-locale, token pipeline) are recorded
  there with rationale; don't re-litigate them casually.

## Hard rules

1. No literal colors/px/shadows/fonts in `src/lib/ui` or `src/routes` — use
   `var(--…)` from `src/lib/tokens/tokens.css`. The only allowed literal is
   `1280px` inside `@media`. `tokens.css`/`tokens.ts` are GENERATED by
   `scripts/gen-tokens.mjs` from `../../docs/design-tokens.json`; edit the
   generator or the export, run `pnpm gen:tokens`, never the outputs.
2. Translations come from the vela-core corpus
   (`../../rust/crates/vela-core/i18n/locales/`), resolved at BUILD time by
   the wasm engine (`src/lib/i18n/engine.server.ts`). Never import that module
   from client code or from the `/` route (the deployed Worker cannot run it),
   and never add a JS-side translation library.
3. `[locale]` routes stay prerendered. New keys: edit all 15 locale namespace
   files, bump the path-count pin in `../../scripts/gen-i18n.mjs`, run
   `npm --prefix scripts run gen:i18n` (repo root; it writes the Rust catalogs
   and `../../assets/i18n/`), then `lint:i18n` + `verify:i18n` must pass.
4. Accent color (`--color-accent-base`) only on the primary value-moving
   action. AA contrast is test-enforced (`contrast.test.ts`).

## Gates before claiming done

`pnpm check` → `pnpm lint` → `pnpm test:unit` → `pnpm build` → `pnpm test:e2e`
(e2e builds and serves the real worker; screenshots land in
`e2e/__screenshots__/` for comparison against `../../design/onboarding/`).

## Svelte MCP

The Svelte MCP server is available (`.mcp.json`): use `list-sections` →
`get-documentation` for Svelte/SvelteKit questions, and run generated Svelte
code through `svelte-autofixer` when authoring non-trivial components.
