# 062 — Plan

> **2026-09-17 ruling:** Part B (replace a key) is dropped, Part A (keys screen) deferred.
> Only **Phase 2 — back up to Ethereum** below is live work; Phases 1 and 3 are kept as
> the record of what was considered. See spec §0 and §5a.

Order is by risk, not by the order the founder listed them: **A reads, C replays bytes
nobody can forge, B moves locks.** A ships alone and is useful alone; B needs A's reads;
C needs only A's row and an Ethereum deployment.

## The shape every part shares

`registry_lookup.rs` (#191) set the pattern and it is kept: **the core is a pure function
of a transcript; a shell performs the requests it is handed and asks again.** No new Crux
operations — four shells match operations exhaustively, so a new one is four compile
breaks; a new exported function is none. Each part adds one such function, exported as
`…Step` through wasm and uniffi, plus view types generated by ts-rs / uniffi records.

## Phase 1 — Part A: the Keys screen (no writes, no risk to funds)

**Core** `rust/crates/vela-core/src/wallet_keys.rs`
- `signer_proxy_key(runtime_hex) -> Option<(x, y)>`: the fixed offsets (`verifiers @0x01`,
  `y @0x27`, `x @0x4d`, `singleton @0x82`), believed only if `singleton`, `verifiers` and
  the re-derived CREATE2 address all match. Test vectors: the two live proxies of
  `0x88cC…6894` (recorded in spec §2) + a truncated, a wrong-singleton and a
  one-bit-flipped runtime.
- `keys_step(address, founding, chains, answers) -> KeysStep`: per chain asks `eth_getCode`
  (Safe) → `getOwners` + `getThreshold` + `getConfiguration` together → `eth_getCode` per
  proxy owner; `Done` carries `Vec<NetworkKeys { chain_id, state, owners: Vec<LiveKey> }>`
  with `state ∈ SameAsFounded | Changed | NotSetUp | CouldNotCheck` and
  `LiveKey ∈ Founding(i) | Replaced { public_key } | Unknown { address }`.
- founding half: extend the #191 walk's hop 3 to return the unit's members WITH
  `attestation` (the index already sends it; `queryUnit` drops it). `attestation_signals`
  (AAGUID, BS) already exists in `create_wallet.rs` — lift it to a shared module and add
  the UV bit. Provider names stay offline (vendored catalog).
- Nothing is cached "for good" here: live means live. One in-memory result per screen visit.

**Shells** — a `Keys` row in each settings home, one screen, read-only:
web `lib/settings/` (third column on wide, per the desktop-web rule: no bottom sheets),
desktop `settings/` (new `Nav::Keys`), Android `feature/settings/`, iOS `Features/Settings/`.
The card is one component per shell, reused by Part B's review.

**i18n**: ~25 new keys × 15 locales. The six corpus gates apply (`reference_i18n_corpus_gates`);
`ru` sits ~150 bytes under the u16 catalog ceiling — check the budget BEFORE writing copy.

**Verify**: SC-621/622/623 live against `0x88cC…6894` (Gnosis: three keys, same as founded;
every other chain: not set up), web + desktop by me, the two phones on device.

## Phase 2 — Part C: back up to Ethereum (bytes nobody can forge)

Blocked on the operator deploying the registry to Ethereum (spec §5). Until then the row is
not drawn — `eth_getCode(registry, chain 1) == 0x` is the gate, read at runtime, so the day
it is deployed the feature appears with no release.

**Core** `registry_backup.rs` — `backup_step(group_public_key, answers)`:
Gnosis `getUnitByGroupKey` → `registerPayloadOf(unitId)` → references → Ethereum
`eth_call(payload)` for the three states → `Done { state, calls: Vec<FeeCall> }`.
The payload is opaque bytes to the wallet; the contract re-verifies every signature, so a
wrong payload costs a reverted estimate, never funds. The existing `SubmitUserOp` path
sends it; the fee row is the ordinary one.

**Needs**: the wallet must know its `groupPublicKey`. It is in the unit the #191 walk finds
— carry it in `WalletName` and store it on the account at next login.

**Restore**: `registry_lookup::step` gains a source parameter: `Index` (today) or
`Chain { chain_id }` — the same three hops as `eth_call`s (`getEntryByKey` →
`getGroupsOfKey` → `getUnit`). Login's index-unreachable rescue (SR5) offers it.

**Verify**: SC-629, on a fork first (anvil `--fork-url` Ethereum with the registry etched at
its address), then for real once deployed.

## Phase 3 — Part B: replace a key (needs the founder's rulings, spec §8)

Built last and behind the parallel space first, because a wrong owner change locks a
person out of a network.

**Core**
- `safe_owners.rs`: encoders for `swapOwner`, `factory.createSigner`, and a MultiSend leg
  with `operation = 1` for `sharedSigner.configure` (today's `encode_multi_send_call` is
  CALL-only). Golden calldata vectors checked against a fork.
- `replace_key_step(...)`: reads live owners, builds the MultiSend, and REFUSES
  (`Done::Stale`) if the owner list differs from the one the review was drawn from.
  `prevOwner` is derived here, never by a shell.
- `Account.signers_by_chain: BTreeMap<u32, Vec<AccountKey>>` + `signer_address_for` takes
  the chain. Empty map = founding set = today's behaviour, byte for byte. The stored
  account shape gains an optional field; old records load unchanged (test with the
  legacy-shape fixtures `login-old-shape.e2e.ts` uses).
- `login.rs`: the references rung (spec B3.2). `registry_lookup`: references fallback and
  the "for good" rule narrowed to "while `getConfiguration` still returns this key" (B3.3).
- Invariants that must keep passing untouched: the `0x762E…329F` identity vector, the
  multi-with-one-key byte identity, the golden multi-key Safe address. None of this work
  may touch `encode_setup_data`.

**Shells**: the five-step flow (spec B1), reusing the add-a-key picker from onboarding, the
key card from Phase 1 and the ordinary confirm/fee/receipt from send.

**Verify** — all with real funds in the parallel space, Gnosis:
SC-624 (proxy key), SC-625 (key 0), SC-626 (stale review), SC-627 (new-key-only login),
SC-628 (wording). Then one real replacement on a second chain to prove "per network".
A negative test that matters more than the positive ones: after replacement, an operation
signed by the OLD key must be rejected by the bundler/EntryPoint.

## What is NOT being decided here

lock" — separate conversations.
