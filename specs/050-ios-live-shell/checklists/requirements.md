# Requirements Checklist — 050 iOS Live Shell

Checked at every phase boundary. A box that cannot be ticked is recorded in
results.md with its reason, never quietly left blank.

## The core decides

- [x] No executor contains a business `if` — no validation, dedup, ordering,
      tombstone, refusal-wording or compatibility decision in Swift.
- [x] The two shell-side presentation judgements (A–Z sectioning, search narrowing)
      are the **only** ones, and each is documented at its site.
- [x] No display rule is duplicated between a fixture builder and a live builder.

## Every operation is answered

- [x] All 27 operations have an answer path; none can return without resolving.
- [x] Failures answer the core's **own** variants — `history_failed`, not `[]`;
      `code: null`, not `""`; `rate: null`, not `1`.
- [x] An unrecognised operation tag answers loudly rather than hanging.
- [x] A cancelled effect is **not** answered.
- [x] Every fail-closed arm carries a `// live in 051` (or `052`) marker, and the
      table of them is complete in results.md.

## Storage is a cross-client contract

- [x] Keys match exactly: `vela.contacts`, `vela.contacts.dismissed`,
      `vela.contactGroups`, `vela.customNetworks`, `vela.networkConfig`,
      `vela.rpcProviders`, `vela.serviceEndpoints`, `vela.displayCurrency`.
- [x] Values are JSON **text**, as `AccountStore` already writes them.
- [x] Stored field names are camelCase with capitalised initialisms — `rpcURL`,
      `logoURL`, `passkeyIndexURL` — not `rpcUrl`.
- [x] Absent optionals are **omitted**, never written as `null`.
- [x] `vela.contacts.dismissed` is written as an **object**, not a list.
- [x] A cleared RPC provider key is **removed**, not stored empty.
- [x] `vela.serviceEndpoints` is reached through `AccountStore`; a saved
      `passkeyIndexURL` survives a `write_service_endpoints`, proven by test.
- [x] Corrupt or absent storage reads empty and never throws.
- [x] A record that round-trips is written back **whole** — no field-by-field copy.
