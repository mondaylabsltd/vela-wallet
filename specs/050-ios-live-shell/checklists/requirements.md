# Requirements Checklist — 050 iOS Live Shell

Checked at every phase boundary. A box that cannot be ticked is recorded in
results.md with its reason, never quietly left blank.

## The core decides

- [ ] No executor contains a business `if` — no validation, dedup, ordering,
      tombstone, refusal-wording or compatibility decision in Swift.
- [ ] The two shell-side presentation judgements (A–Z sectioning, search narrowing)
      are the **only** ones, and each is documented at its site.
- [ ] No display rule is duplicated between a fixture builder and a live builder.

## Every operation is answered

- [ ] All 27 operations have an answer path; none can return without resolving.
- [ ] Failures answer the core's **own** variants — `history_failed`, not `[]`;
      `code: null`, not `""`; `rate: null`, not `1`.
- [ ] An unrecognised operation tag answers loudly rather than hanging.
- [ ] A cancelled effect is **not** answered.
- [ ] Every fail-closed arm carries a `// live in 051` (or `052`) marker, and the
      table of them is complete in results.md.

## Storage is a cross-client contract

- [ ] Keys match exactly: `vela.contacts`, `vela.contacts.dismissed`,
      `vela.contactGroups`, `vela.customNetworks`, `vela.networkConfig`,
      `vela.rpcProviders`, `vela.serviceEndpoints`, `vela.displayCurrency`.
- [ ] Values are JSON **text**, as `AccountStore` already writes them.
- [ ] Stored field names are camelCase with capitalised initialisms — `rpcURL`,
      `logoURL`, `passkeyIndexURL` — not `rpcUrl`.
- [ ] Absent optionals are **omitted**, never written as `null`.
- [ ] `vela.contacts.dismissed` is written as an **object**, not a list.
- [ ] A cleared RPC provider key is **removed**, not stored empty.
- [ ] `vela.serviceEndpoints` is reached through `AccountStore`; a saved
      `passkeyIndexURL` survives a `write_service_endpoints`, proven by test.
- [ ] Corrupt or absent storage reads empty and never throws.
- [ ] A record that round-trips is written back **whole** — no field-by-field copy.

## Fixtures stay canon

- [ ] `SettingsFixtures.swift` and `ContactsFixtures.swift` diffs are additive only.
- [ ] Every gallery state and every `VELA_PAGE=`/`VELA_STATE=` route renders exactly
      as before, proven by the screenshot sweep.
- [ ] Live builders produce the **same** display model types the fixtures produce.
- [ ] Before the core has ruled, the screen shows a neutral surface — never fixture
      data posing as the visitor's own.
