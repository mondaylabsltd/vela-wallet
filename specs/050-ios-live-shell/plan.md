# Implementation Plan: iOS Live Shell — Settings and Contacts on the Core

**Branch**: `050-ios-live-shell` | **Date**: 2026-09-05 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/050-ios-live-shell/spec.md`

## Summary

Wire three storage-only Crux machines — `contacts`, `network_admin`,
`display_currency` — into the SwiftUI client, so 通讯录 stops being a dead tab and 设置
stops showing a stranger's networks. Pay once for the plumbing every later cut reuses:
three `bridge_object!` exports, a resident `CoreStore` over the existing `CoreDriver`,
a `VelaStore` that generalises `AccountStore`'s JSON-text-in-`UserDefaults` contract,
a small `CoreHTTP`, and a `Decodable` view seam. `network_admin`'s probes are the only
network in the cut; everything whose infrastructure belongs to 051 or 052 is answered
with the core's own unknown variant and marked. One new control — a text field —
because the add-network wizard is drawn without one and therefore cannot be used.

## Technical Context

**Language/Version**: Swift 5.9 / SwiftUI on iOS 17.4+; Rust 1.97.1 for the
(unchanged) machines and the uniffi bridge.

**Primary Dependencies**: existing only — `VelaCoreKit` (uniffi, local SPM package
over a locally built `.xcframework`), `CoreDriver` (spec 019), `AccountStore` (spec
019), `Foundation.URLSession`. No new packages, no CocoaPods, no SPM additions.

**Storage**: `UserDefaults.standard`, values as **JSON text** under `vela.*` keys —
the format `AccountStore` already uses and the one web writes to `localStorage` and
Expo to `AsyncStorage`. No new store, no CoreData, no files.

**Testing**: Swift Testing / XCTest in `VelaWalletTests` (executors, live builders,
storage, view-decode drift); XCUITest in `VelaWalletUITests` for the existing
screenshot sweep; device verification on `shelchin's iPhone` for every P1 scenario.

**Target Platform**: iPhone, iOS 17.4+ (the deployment target `VelaCoreKit` and the
app agree on, for `excludedCredentials`).

**Project Type**: native mobile app (`app-ios/VelaWallet`) + a Rust FFI bridge crate.

**Performance Goals**: no regression to cold start; a settings or contacts interaction
renders from the committed core view within one frame of the view callback — local
storage operations show no spinner, network probes show the drawn busy state.

**Constraints**: zero lines under `rust/crates/vela-core/src/app/`; zero corpus delta;
tokens only, no literal colours/spacing/radii/type; no business `if` in executors;
`vela_core_uniffi.swift` regenerated by script, never hand-edited; the four other
clients untouched.

**Scale/Scope**: 3 machines, 27 operations, 2 screens, 1 new control. Roughly 5 shared
plumbing files plus ~3 files per machine; the Swift test count grows by ~20.

**Structure Decision**: a new `Core/` directory holds everything that is blind to which
machine it is driving, so the per-machine cost is exactly three files — executor, live
builder, wire mirrors — plus a store that is a dozen lines. That shape is what SC-004
measures on the third machine, and it is what specs 051–053 inherit.

`Features/Onboarding/Core/` keeps `CoreDriver` where it is. Moving a file that three
live machines already depend on, in the same commit that first reuses it, buys nothing
and risks the one part of the app that works. The move is noted as debt.

## Phases

Each phase is one commit, and each ends on a green gate: `xcodebuild build`,
`xcodebuild test`, the literal audit, and the screenshot sweep.

| # | What lands | Proves |
|---|---|---|
| 0 | Baselines recorded: test count, binary size, sweep output, the 27-operation inventory | Nothing is claimed that was not measured |
| 1 | The road + the first machine: 3 exports, `Core/`, `VelaStore`, `CoreHTTP`, and **contacts** wired; 通讯录 opens | The pipeline works end to end, on the smallest machine, with no network |
| 2 | `network_admin` reads: store, search index, chain info | The largest machine's read half, and the first real HTTP |
| 3 | `SettingsField` + the add-network wizard's write path: probes, verdicts, refusal, persist | The one drawing gap closed, and the core's verdict on screen |
| 4 | **`display_currency`** — the paved-road measurement | SC-004: the third machine costs zero shared lines |
| 5 | Contacts writes: edit, delete, tombstone, groups, and the `AccountSwitched` boundary | SC-001 on the device |
| 6 | Device verification, blocked-surface table, debts → 051, results.md | SC-008 |

The order is deliberate and differs from a naive "smallest first": contacts is first
because it needs no network and therefore isolates the pipeline from the HTTP layer;
`display_currency` is **third**, not first, because the paved-road measurement is only
meaningful once the road has been paved by two machines with different needs. This is
the same correction desktop's 030 made mid-flight and recorded.
