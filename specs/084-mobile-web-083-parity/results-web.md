## NO MONEY: how it was enforced, and what "slide" means in this file

Nothing in this file touched a chain. The hand-off's revert/neighbour/inner/pending shim modes wrap a real relay submission; those steps are **HELD-money** as written. I ran the same code paths for free instead:

1. **Network-layer guard.** Every panel/window target I attached got CDP `Fetch.enable`; any POST whose JSON-RPC method is `eth_sendUserOperation`, `eth_sendRawTransaction`, `eth_sendTransaction`, `wallet_sendCalls` … is answered by me with `VELA-CHECK-GUARD: write blocked by the check harness (no money)` and never leaves the browser. **Proven before every slide** by an XHR (which the in-page shim does not wrap) posting `eth_sendUserOperation` with empty params to the relay: it got the guard's answer (`guard probe (XHR bypassing the shim) -> {"…"error":{"code":-32000,"message":"VELA-CHECK-GUARD: …"}}` at the top of every `W-*.txt`/`synth-*.txt`).
2. **In-page shim** (the hand-off's, extended: `probe/shim.js`). `eth_sendUserOperation` is never forwarded: `pending`/`aa25` answer with the relay's "already pending [existingHash:…]" wording; `synth` answers with a fabricated op hash and later serves a **fabricated receipt cloned from a REAL past receipt of the same Safe** (Gnosis op `0xcc307e63…5b90`, fetched read-only from the relay), with `success:false` (revert), an ExecutionFailure ahead of BeforeExecution (neighbour) or inside the op's own span (inner). The wallet's own code (`waitForReceipt`, tx-reconciler, tracker, sign-executor, feed) runs end to end on it.
3. "**Slide**" below therefore means: signed with the fixture key (no prompt) and answered by the synthetic relay. Each such run ends with `shim log` (what the shim answered) and `guard log` (only my probe). No real userOp, tx or approval was sent by me.
4. **One mistake, disclosed**: in the first `W-H2-approve` run the "Custom" cap chip was not hit, and the **uncapped 2^254 approve** was slid against the synthetic relay (the sheet said "Unlimited — this contract can spend all your tokens"). The signed op lives only in that page's memory (the log stores a 200-char prefix); it was answered by the shim, never sent. The next run aborts if the cap is not applied and slid only the capped one (`1 USDC`). §3 forbids sliding an unlimited approve as asked; this was against the fake relay, but it should not have happened.
5. Also slid against the synthetic relay: the real Uniswap swap sheet (0.03 USDC → ETH on Base, `W-uniswap-rebuilt.txt`). Site chain forced to Base (`0x2105`) before anything was asked; Ethereum mainnet never selected for a sheet.
6. **Note for the coordinator**: a real op landed on the shared MultiTest Safe on Gnosis at 10:37:20 local (nonce 61, tx `0xf7ffc22b47bd…`, balance 0.13967 → 0.12867 xDAI). It is **not mine** (my guard log has only the probe; my sends were synthetic). Another client/agent is spending; this is why my later sheets show nonce `0x3e`.
