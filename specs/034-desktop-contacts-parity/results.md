## Phase 1 — 两个"从来没人问过"的问题

### 一、打开联系人时,没人去查这个地址

web 每打开一条通讯录,就 dispatch 一次 `InspectRecipient`。桌面**一次也没发过**。

后果不是少了一个标签,而是:**核心会把查到的身份写回那条联系人**
(`resolved_name`,它自己的 RecipientTrust 写回),而这只壳从 031 起就在读
`resolved_name` —— 读的是一个**永远没人填**的字段。也就是说,一条"存了地址、没起名"的
联系人,在桌面上永远显示 `0x1234…5678`,而网络本来能说出它的名字。

现在打开详情就问一次(按地址去重 —— 面板每帧都画;核心自己也缓存去重,两道都便宜)。
分类用链 1,和 web 一样的理由、一样的措辞:在发送流程指定之前,主网。

一条测试钉住这条**因此才可达**的优先级:自己起的名 > 核心查到的名 > 缩写地址,
而且空字符串不是名字(另一个客户端写的库里,两个字段都可能是空串而不是缺席)。

### 二、账户面板只会说"有几个",不会说"有多少"

`SwitcherOpened` / `SwitcherClosed` 没接过。031 的注释老老实实写着为什么没有金额:
"这个面板没有做那次 `balance_dashboard` 读取"。于是那句摘要一直停在
**`1 accounts · `** —— 一个吊着的间隔点,等着从来没来的后半句
(`assets.switcherTotal` 这个字符串**早就解析好了**,只有画稿在用)。

现在:打开面板 = 打开切换器(核心在它开着的时候刷新每个账户的总额),离开就说一声 ——
**没人关的订阅就是轮询**,所以设置区换页、侧栏换区都会关。每行的钱和摘要里的合计,
都只统计**核心真的有缓存的那些**:没有数字的账户什么都不写,而不是写 `$0` ——
英雄区的不变量②对每一个账户都成立,不只对当前这个。

合计用 USD,和这只壳里其他总额一样:换算归 display_currency,而它的汇率可以是 `None`
—— **`None` 不是 1** —— 在这里换算就成了全应用唯一一处瞎猜。

### 实机

`1 accounts · Total $0.75`,行尾 `$0.75`。

desktop **345 / 341**(+1 测试),fmt clean,画廊全渲染,Windows 通过。

### 顺带记下:这一刀原本要做的事,被复核撤了

**交易模拟的余额变化预览**不是对齐工作。web **确实跑** `eth_simulateV1`、
用 `token_trust` 判定每一笔 delta、把结果写进 `SendView::sim_json` 和签名记录的
`assetChanges` —— **两个都没有任何地方读回来**。画它的那个块(`kind: 'balances'`)
在 web 只出现在 `signing/fixtures.ts`,在这边只出现在 `signing/fixtures.rs`:
**两个画廊都画了,两端都没接。**

桌面 `SimulateCalls` 那句注释本来就是诚实的读法,继续成立:
"桌面还没有模拟引擎:确认面保持空白,这是'尽力而为'的诚实读法。"
要做的话它是个**新功能**(而且是个好功能 —— 签名面板上唯一一处恶意站点无法伪造的内容),
需要一个引擎,不是接一根线。

## Phase 2 — 分组终于能装人了

`SetContactGroups` / `SetGroupMembers` 两个事件,web 都从真界面点得到
(一条联系人的"移入分组",一个分组的"添加成员")。桌面**一个都没发过**,
而后果是可以说出来的:**分组能建、能改名、能删,就是永远装不进人。**

### 一个从 spec 018 起就画着、从没被打开过的菜单

联系人行的右键菜单(转账/收款/复制/编辑/移入分组/删除)在组件板上画了六项,
**没有任何地方打开它**。而 DC2 的注释早就写明:桌面加分组的入口就是这个菜单里的"移入分组"
—— 所以手机那个 `+ 分组` 芯片才没有出现在详情面板上。也就是说,**入口一直指向一扇没装的门。**

六项现在都有地方去(这也是它终于被打开的原因):转账带着这个人进发送流程
(`prefilled_recipient` —— 预填是核心接的,壳不往自己的屏幕里打字)、收款、复制地址、
编辑(同一张表单,地址固定 —— 地址就是身份,改地址的"编辑"其实是一删一加穿着一个按钮)、
移入分组、删除。

### 勾选就是状态

"移入分组"开的是第二层菜单:每个分组一行,**这个人已经在的那些画对勾**,
不在的画分组图标。点一下就把**整份成员关系**送回去(`SetContactGroups` 是核心给的形状,
它自己会归一化)。不做"保存"按钮,因为这个问题是"这些里面哪些",而一行一个勾是同时
问出问题和给出当前答案的最短写法。

**一条测试钉住会静默出错的地方**:勾一个分组,**其他分组的成员关系必须原样留着**。
菜单正好盖住了会显示这个损失的芯片,所以一个"从被点的那个分组重建集合"的写法,
会把这个人从别的所有分组里悄悄拿出来 —— 而等人关掉菜单看到时,核心已经被告知了。

### 诚实的边界

右键菜单本身**没能在实机上验**:今天这台机器的合成输入在这一片不落点(左键、右键都试过),
032 交接里已记过这条坑。它照抄的是分组行和 Recent 行同一套已验证过的右键模式,
而会出错的那条规则由上面那条测试守着。

desktop **346 / 342**(+1 测试),fmt clean,画廊全渲染,Windows 通过。

## Phase 3 — 从分组这一侧,把同一个问题问一遍

重跑对照(见下)后剩下的"强"差集里,`SetGroupMembers` 是唯一一件真活:
分组屏上那行 **"添加成员" 从 spec 018 起就画着,没有监听器**。phase 2 从联系人那侧
解决了成员关系,这一刀从分组那侧。

**一个形状,两个方向**:两边都是"这些里面哪些",两边都是一次点击送回**整份集合**
(`SetContactGroups` / `SetGroupMembers`),所以菜单是同一个 `pick_menu`,
翻转规则是同一个 `set_after_toggle`(改名自 phase 2 的那个)——
两份形状就是两处可以把勾画错的地方。

### 实机(真的动了数据)

Family 分组 → 添加成员 → 菜单里 Alice / Bob 各一行 → 点 Alice:
左边导轨的计数变 1、标题变 `1 members`、Alice 出现在成员列表里,
`wallet.json` 的 `vela.contactGroups` 里 family 的 members 真的多了那个地址。

desktop **346 / 342**,fmt clean,画廊全渲染。

## 这一刀结束时的重跑对照

把方法又跑了一遍,这次**把可达性判定写进了脚本**:web 的 dispatch 落在
`routes/` 或 `.svelte` 里 = 强(有界面点得到),只落在 `lib/**/core/*.ts` 里 = 弱
(要人去查有没有调用者)。

**42 → 15**,其中强的只剩 5 条:

| 事件 | 判定 |
|---|---|
| `contacts.SetGroupMembers` | ✅ 本 phase 做掉 |
| `send.OpenScanner` / `CloseScanner` / `ScanResolved` | 扫码 —— 桌面没有相机管线,**平台功能不是接线** |
| `sign_request.RejectTapped` | ❌ **不是差集,是故意的偏差**:桌面的签名词汇表里**没有拒绝按钮**,关掉这一列就是拒绝(`signing/fixtures.rs` 自己写着),而那个 X 发的是 `SwipeDismissed` —— 核心按阶段路由它(未提交→拒绝 4001、已提交/出错→仅关闭、充值页→取消充值),**比一个硬拒绝更准**。 |

弱的 10 条里,已经查过并撤下的:历史行删除、自定义代币删除、报价过期 `Requote`、
交易模拟 `SimDeltasComputed`。剩下 `LeaveConfirm` / `MessagePresented` / `LinkOpened` /
`FundingCancelled` / `PopupRequest` / `Abort` —— 前面几个要逐个查调用者,
`PopupRequest` 是扩展专用,`Abort` 是拆卸时的内部事件。
