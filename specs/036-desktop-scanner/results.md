# 036 · Desktop Scanner — results

分支 `036-desktop-scanner`,叠在 035 上。

## Phase 1 — 不用相机的那一半(而且三个桌面都能用)

DS1 从 spec 021 起就是一张画:取景框、一句提示、两个工具按钮,**背后什么都没有**。
这一刀接的是**从图片里读码**——截图、别人发来的照片、这只钱包自己存出去的分享卡。

三块:

1. **解码**(`executor/qr.rs`,`rqrr`,纯 Rust —— 不要 zbar、不要 C 工具链,
   **这条路不能成为某个平台编不过的理由**)。答的是"图里有什么字",
   **它不判断任何事**。
2. **`ethereum:` 分词**(`flows/eip681.rs`,照 web 的 `eip681.ts` 移植),
   **两条用真 bug 换来的拒绝原样保留**:
   - `/transfer` 里的 `value` **不是**代币金额(它是随调用附带的以太),
     照它读会把"附带 1 ETH"变成一笔锁定的 10¹² USDC;
   - **任何别的函数都不是付款**(`approve` 曾经掉进原生分支,把**代币合约**
     当成收款人 —— 一次伪装成付款的销毁)。
3. **路由**(照 web 写好的那份):发送流程里由**核心**裁决(`ScanResolved`);
   从首页扫则**开一个新的发送**,预填,并且**恰好在请求指明链的时候锁定**。

### 顺手抓到一个真 bug

扫码弹层的卡片**在遮罩里面**,而遮罩自己带着"点一下就关"。所以点卡片上的任何东西
——包括它的工具按钮——都会冒泡到遮罩的关闭:**工具触发了,然后它打开的屏幕在它背后被清掉。**
第一次实机就撞上了(扫描成功、发送打开、随即被关)。这只壳里其他覆盖层早就都拦了这一下;
这一个是在**还没有东西可点的时候**画的,所以从来没人发现。

### 一个新的 env 钉

`VELA_SCAN_FILE=<路径>` 跳过文件对话框 —— 和 `VELA_GALLERY_TAB` / `VELA_FLOW` 同一族,
理由也一样:**文件对话框是系统窗口,这个 app 驱动不了它**,没有这个钉,
任何截图流程和无头运行都永远到不了扫码的另一侧。

### 实机(真读了一张图,真开了一笔钱)

用 `#[ignore]` 的那条测试写出一张 `ethereum:0x88cCA0…6894@100?value=10000000000000000`
的 PNG,然后在 parallel space 里点 扫码 → 从相册:
**Send xDAI 开了,锁在 Gnosis,金额 0.01(≈$0.01),收款人是那个地址
(而且被认出来是"MULTITEST · SELF"),Continue 亮着。**

desktop **357 / 353**(+7 测试:解码往返、非图片/空图、EIP-681 五条),
fmt clean,画廊全渲染,Windows 通过。

## Phase 2 — 取景框里真的有画面了

`nokhwa`,只开 `input-avfoundation` 一个后端,而且**只在 macOS 目标下**依赖 ——
这是**分级,不是缺口**:phase 1 的"从图片"是扫码的**地板**,三个桌面都站得住,
所以没有采集后端的平台失去的是预览,**不是这个功能**。只点名 avfoundation 也是同一个道理:
点上 v4l 或 Media Foundation 会把那两个系统的头文件拖进不编译它们的目标里。

### 全部失败都是软的

没相机、相机被别的 app 占着、有人对权限说了不、驱动给回这份构建解不了的格式 ——
落点都一样:`failed`,取景框保持空井,而工具条上"从图片"那扇门还在原地。
**一只因为摄像头忙就崩掉的钱包,比一只安静地指另一扇门的钱包更糟。**

### 一条自己的线程,不是异步任务

`Camera::frame` 会阻塞到传感器给完为止。放在 gpui 前台就是窗口不画;
放在它的后台执行器上,就等于在一个小池子里占着一条线程直到扫码结束。
所以采集自己占一条线程,把最新帧塞进 mutex,屏幕读最新的那张 ——
和 `wallet::money` 的仪式同一个形状。

### 帧的纪律,这是第二处需要它的地方

`RenderImage::new` 每次都取一个新的 `ImageId`,渲染器按 id 缓存 GPU 纹理 ——
预览一秒钟就要发三十帧,**不还就是一秒漏三十张纹理,而且屏幕上完全看不出来**。
`contracts/desktop-frame-pump.md` 当年为开机动画写下这条规矩;
`ScanPreview::replace` **把被换下来的那一张交还给调用者**,所以"忘记释放"必须写成
一句看得见的丢弃才做得到。离开扫码时相机和那张帧一起走。

相机给的是 RGBA,渲染器要的是预乘 BGRA —— 每像素两次交换,就地做,不多一次拷贝。

### 实机

parallel space 里点 扫码:**取景框里是真的摄像头画面**(颜色正确,没有通道错位)。
关掉弹层,窗口还活着,相机和帧一起释放。

**没能自己验的那一半**:把一张 QR 举到镜头前 —— 那要人动手。
解码用的是文件那条路同一个 `rqrr`(有往返测试),
解到之后走的也是 phase 1 已经端到端验过的那条 `scan_resolved`。

desktop **357 / 353**,fmt clean,画廊全渲染,Windows 通过
(Windows 上这条依赖根本不在图里 —— 这正是把它挂在 macOS 目标下的原因)。
